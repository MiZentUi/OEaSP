**Некоторые служебные и технологические задачи**

**1\. Цель работы**

Изучить системные механизмы операционной системы Windows, используемые для конфигурирования, мониторинга, журналирования, обработки оконных сообщений и построения многомодульных приложений.

В ходе выполнения лабораторной работы необходимо:

\-      изучить назначение и структуру реестра Windows;

\-      освоить программные интерфейсы для чтения, поиска, изменения и контроля данных реестра;

\-      получить навыки сбора и анализа системной информации;

\-      изучить механизмы журналирования событий Windows;

\-      освоить средства перехвата и протоколирования оконных сообщений;

\-      изучить принципы построения динамически подключаемых библиотек DLL;

\-      освоить способы загрузки и использования внешних программных модулей;

\-      приобрести навыки разработки служебных и диагностических утилит;

\-      научиться обрабатывать системные ошибки и корректно освобождать ресурсы;

\-      закрепить навыки использования Git для сопровождения разработки.

**2\. Теоретическая и методическая часть**

Перед выполнением лабораторной работы необходимо изучить следующие вопросы.

**2.1. Конфигурирование Windows**

\-      Назначение реестра Windows.

\-      Иерархическая структура реестра.

\-      Разделы и значения реестра.

\-      Основные корневые разделы.

\-      Типы данных REG\_SZ, REG\_EXPAND\_SZ, REG\_DWORD, REG\_QWORD, REG\_MULTI\_SZ, REG\_BINARY.

\-      Права доступа к разделам.

\-      Создание, открытие, перечисление и удаление разделов и значений.

\-      Экспорт и восстановление данных реестра.

\-      Обнаружение изменений.

Основные функции Windows API:

| **Функция**               | **Назначение**               |
| ------------------------- | ---------------------------- |
| RegOpenKeyEx()            | Открытие раздела             |
| RegCreateKeyEx()          | Создание раздела             |
| RegQueryValueEx()         | Чтение значения              |
| RegSetValueEx()           | Изменение значения           |
| RegEnumKeyEx()            | Перечисление подразделов     |
| RegEnumValue()            | Перечисление значений        |
| RegDeleteValue()          | Удаление значения            |
| RegDeleteKeyEx()          | Удаление раздела             |
| RegDeleteTree()           | Удаление дерева подразделов  |
| RegNotifyChangeKeyValue() | Ожидание изменения реестра   |
| RegCloseKey()             | Закрытие дескриптора раздела |

**3\. Общая постановка задачи**

Разработать приложение или программный комплекс для Windows в соответствии с индивидуальным вариантом.

Приложение должно демонстрировать непосредственную работу с указанными механизмами операционной системы.

В зависимости от варианта необходимо реализовать:

\-      утилиту работы с реестром;

\-      приложение мониторинга изменений;

\-      средство анализа и очистки учебных данных реестра;

\-      приложение сбора системной информации;

\-      средство анализа или записи событий;

\-      приложение перехвата оконных сообщений;

\-      многомодульное приложение с DLL.

Основная функциональность должна использовать соответствующие системные интерфейсы Windows API.

**Основной язык программирования — C или C++.**

Для варианта со смешанной сборкой допускается и предусматривается использование C++/CLI.

Использование Python, MATLAB, R и других языков допускается для обработки экспериментальных результатов, построения графиков и дополнительных проверок.

Использование готовых библиотек не должно полностью заменять изучаемый механизм Windows API.

Программа может быть консольной или оконной. Если для выполнения варианта необходима обработка оконных сообщений, оконная часть является обязательной.

**4\. Общие требования к реализации**

**4.1. Параметры программы**

Основные параметры должны задаваться без изменения исходного кода.

В зависимости от варианта необходимо предусмотреть:

\-      путь к разделу реестра;

\-      образец поиска;

\-      максимальную глубину обхода;

\-      количество объектов;

\-      интервал наблюдения;

\-      количество измерений;

\-      формат экспорта;

\-      режим работы;

\-      выбранную библиотеку;

\-      количество операций;

\-      параметры фильтрации.

Допускается использование аргументов командной строки, консольного меню, конфигурационного файла или графического интерфейса.

**4.2. Ограничение области работы с реестром**

Для операций изменения и удаления данных разрешается использовать исключительно специально созданную учебную область:

HKEY\_CURRENT\_USER

  \\Software

    \\OSiSP

      \\Lab06

        \\Student\_<STUDENT\_ID>

          \\Run\_<RUN\_ID>

Студент самостоятельно создает необходимые подразделы и значения.

**Изменение или удаление данных за пределами учебной области запрещается.**

Поиск и просмотр системных разделов допускаются только в режиме чтения и в пределах прав текущего пользователя.

Не допускается изменение системных параметров Windows, параметров безопасности, автозагрузки и конфигурации установленных приложений.

**4.3. Ограничения на использование WinHook**

Перехват оконных сообщений допускается только для окон и потоков собственного учебного приложения.

Не допускается:

\-      установка глобальных перехватчиков для всех приложений;

\-      запись текста, вводимого пользователем в посторонних программах;

\-      перехват сообщений чужих процессов;

\-      скрытая регистрация действий пользователя;

\-      использование механизмов внедрения DLL в сторонние процессы.

**4.4. Проверка системных вызовов**

Каждый существенный вызов Windows API должен сопровождаться проверкой результата.

При ошибке необходимо отображать:

\-      название функции;

\-      код ошибки;

\-      текстовое описание;

\-      выполнявшуюся операцию.

Для функций реестра, возвращающих код состояния непосредственно, необходимо использовать возвращенный код, а не автоматически обращаться к GetLastError().

**4.5. Освобождение ресурсов**

После завершения приложения необходимо освобождать:

\-      открытые разделы реестра;

\-      системные дескрипторы;

\-      установленные оконные перехватчики;

\-      подключенные динамические библиотеки;

\-      объекты ожидания;

\-      выделенную память;

\-      другие ресурсы, созданные программой.

**4.6. Журналирование**

Программа должна вести журнал основных действий.

Для каждого события указывать:

\-      время;

\-      тип операции;

\-      объект;

\-      результат;

\-      код ошибки при наличии.

Пример:

\[10:15:01.125\] REG\_OPEN status=OK

\[10:15:01.131\] REG\_ENUM key=Settings count=12

\[10:15:01.142\] REG\_EXPORT file=backup.json

\[10:15:01.150\] REG\_CLOSE status=OK
